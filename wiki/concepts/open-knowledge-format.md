# Open Knowledge Format (OKF)

OKF is an **open** format for representing knowledge: the metadata, context,
and curated insight that surrounds data and systems. It is designed to be
authored by people, generated by agents, exchanged across organizations, and
consumed by both.[^okf-spec]

## Why it exists

Knowledge for AI agents is fragmenting into incompatible conventions. OKF's
position: knowledge is best in **commonly accessible, established formats** that
are readable by humans, parseable by agents, diffable in version control, and
portable across tools/time.[^okf-spec]

## Core shape

A *bundle* is a directory tree of markdown files. Each file is one *concept*
with two parts:

1. **YAML frontmatter** (`---` delimited) — structured metadata.
2. **Markdown body** — free-form content, preferably structured (headings,
   tables, fenced code).

The only always-required key is `type`. A concept with just `type` is fully
conformant.

## First-class trust/lifecycle fields

- `sources` — provenance (what this was derived from) + credibility signals
  (`author`, `usage_count`, `last_modified`).
- `generated` / `verified` — who wrote it / who confirmed it (actor convention
  `human:<id>`, `<agent>/<version>`, `process:<id>`).
- `status` — `draft | stable | deprecated`.
- `stale_after` — absolute ISO-8601 instant after which the concept is stale.

Per-claim attribution uses markdown footnotes keyed to `sources[].id`, e.g.
`[^okf-spec]`, so agents can rewrite text without misattributing.

## Why this base uses it

OKF gives the LLM-maintained wiki a *trustable* spine: every page records where
it came from and how much to trust it, instead of a flat pile of LLM prose.
